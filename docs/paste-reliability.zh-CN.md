# 粘贴目标交接与图片写回

适用于原生 2.x 的 macOS、Windows。记录点击、选中后回车、片段粘贴、全局快速粘贴和纯文本粘贴使用同一交接流程。

## 目标窗口就绪后才注入

写回剪贴板、等待修饰键之前，先由原生命令循环保留有效的外部目标。写好剪贴板后，原生面板结束编辑并释放键盘；未固定时隐藏，固定时继续可见。应用最多等待一秒，确认原先的目标仍在真实前台、键盘交接也已就绪，再发送一次系统粘贴键。等待修饰键期间不会重新选择别的目标；命令通道关闭、目标失效或等待超时时停止注入。

macOS 保留实际的 `NSRunningApplication` 实例，并检查运行状态、真实前台及 NSPanel 的 key 状态。固定面板交接后，显式点击或再次按打开快捷键可重新取得键盘。

Windows 保留 HWND 与所属进程 ID，检查窗口仍有效、所有者未改变、非激活面板已释放输入。发送 `Ctrl+V` 前再次检查目标、前台与修饰键。Windows 拒绝前台切换或按键注入时返回失败，不尝试提权或附加输入线程。

重叠操作通过进程内协调，过期任务不能继续注入。用户重新打开、编辑或取消面板，以及显式复制，会使待交接的任务失效。控制事件在生产端同步取消，再排队执行窗口操作；晚到的旧事件按原时间戳判断，不会取消新的操作。交接和权限失败时，已写好的内容留在系统剪贴板，列表提示可手动粘贴。

系统按键注入仍依赖目标程序是否支持该格式，也不能绕过 Windows 完整性级别、系统安全输入或 macOS 辅助功能权限。目标从原生 Capture 完成起固定；系统热键事件到 UI 处理 Capture 之间仍有调度间隔，前台验证与系统消费按键之间也不存在跨进程原子保证。

## macOS 设置窗口前台交接

设置、引导和备份导入使用普通 NSWindow，在 GPUI 窗口借用结束后的主线程任务中激活应用并执行 `makeKeyAndOrderFront`；最小化窗口先恢复。任务持有原生窗口并检查 GPUI 句柄仍有效，关闭后的窗口不重新显示。剪贴板面板继续保持非激活策略。

设置已取得键盘且没有待执行粘贴交接时，迟到的面板隐藏/输入释放不再恢复之前的外部应用。真正的粘贴交接仍检查原目标和权限。

## 重编码图片的回环抑制

保留原有 PNG 字节写回及内容哈希快路径。如果操作系统重编码 PNG，使字节不同但像素相同，则在两秒的登记期限内使用宽高与 RGBA 指纹辅助识别自身写回。原始哈希或像素指纹任一命中即消费同一登记，避免稍后再次吞掉真实复制。

辅助识别只处理不超过 20 MiB、4000 万像素的 PNG，decoder 分配上限 200 MiB、RGBA 上限 160 MiB；格式转换时两份缓冲可能短期共存。失败或超限时退回原始哈希路径，不阻止写回。

不新增数据库迁移，不改原图、已存记录或内容哈希。监听保持先构建记录、再检查写回守卫的顺序，因此被抑制的重编码回显可能产生辅助 PNG 文件，但不新增历史记录。

## 验证入口

- `cargo test --locked --workspace`
- `cargo clippy --locked --workspace --all-targets -- -D warnings`
- `cargo fmt --check`（不加 `--all`）
- macOS 设置窗口：`KWIKPASTE_SELFTEST=1 ./target/debug/KwikPaste --selftest-preferences`，真实检查 AppKit visible/key/active 状态，未满足时退出失败；自测使用独立数据与内存剪贴板。
- Windows 测试机：`tools/platform-probes/paste.ps1 -UiPanel -QuickPaste -PastePlain`，检查脚本自己的文本窗口确实收到一次粘贴。
- Windows 测试机：`tools/platform-probes/image-paste.ps1`，检查真实系统剪贴板、合成图片接收与写回回环。

原生探针要求独立测试身份和可交互桌面；检测到已安装的 KwikPaste 正在运行时拒绝测试，以免合成内容进入用户历史。普通工作区单元测试不操作用户剪贴板。
